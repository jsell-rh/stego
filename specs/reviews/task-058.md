# Review: Task 058 — Wire Before-Operation Lifecycle Slots into Rest-API Generator

**Reviewer:** Verifier
**Commit under review:** a2e6216, 64102c6

## Findings

- [x] [process-revision-complete] **`existing_entity` in `before_patch` contains post-merge state, not pre-patch state.** The `emitBeforePatchSlot` function builds `existingEntityMap` by reading from the entity variable (`lower`, e.g. `profile`) at Step 4 of the generated patch handler. But Step 3 has already applied non-nil patch fields to this same variable (`profile.DisplayName = *patch.DisplayName`). The proto field is named `existing_entity` and the spec (line 312) describes the input as "Patch fields + existing entity + caller." Both the proto name and spec description unambiguously indicate the pre-patch state. As implemented, a fill receiving `existing_entity` cannot determine the original field values before the patch was applied — it sees the merged result. This defeats the stated use case of "Enforce field-level permissions" because the fill cannot compare old vs. new values. **Fix:** Move the `before_patch` slot invocation to before Step 3 (before applying patch fields to the entity variable), or capture the existing entity state into a separate variable before mutation and use that for `existingEntityMap`. File: `internal/generator/restapi/generator.go`, lines 1392–1411. **Resolved in 64102c6.**
- [ ] [process-revision-complete] **`emitBeforeDeleteSlot` uses `EntityId` but the slot interface struct field is `EntityID`.** The `emitBeforeDeleteSlot` function at `generator.go:3704` hardcodes the struct field name `EntityId:` (lowercase 'd') in the generated handler code. However, the slot interface generator's `protoFieldToGoName` function converts `entity_id` to `EntityID` (uppercase 'D') — the `ID` suffix is a special-cased Go acronym (confirmed by `TestProtoFieldToGoName` at `generate_test.go:327`: `"user_id"` → `"UserID"`). The generated handler code writes `EntityId: id,` but the `BeforeDeleteRequest` struct generated from `before_delete.proto` will have the field named `EntityID`. This is a Go compile error in the generated output. The test at `generator_test.go:9623` passes only because it uses `strings.Contains` to match the (incorrect) handler output, not because the generated code compiles. **Fix:** Change `generator.go:3704` from `EntityId` to `EntityID`. Also update the test assertion at `generator_test.go:9623` from `"EntityId:"` to `"EntityID:"`.
